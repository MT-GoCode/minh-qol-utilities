# Uncertainties squashed

1. **Directory watching.** Probe `scratch/s14-probe/probe.swift`, `config.json` in a directory, five edits: create, in-place truncate+write, atomic rename (`Data.write(.atomic)`), an unrelated file, delete. A dispatch source on the directory fired for all but the in-place overwrite; one on the file descriptor misses the atomic rename (the descriptor keeps the old inode). FSEvents on the directory (latency 0.05 s, `NoDefer`) fired for **all five** within 12 ms, so `DirectoryWatcher` uses it: an editor that saves in place (`echo >`, nano) and one that renames (vim) both work. 0.05 s only coalesces a truncate+write pair. FSEvents also fires for unrelated files and for `transcripts/` (the config sits in the data root); `reload` publishes only a change of `(config, error)`, so those cost one tiny read. The callback ignores its `paths` argument (without `kFSEventStreamCreateFlagUseCFTypes` it is a `char **`; casting it to `NSArray` segfaulted the first probe).
2. **`ClosedRange<Int>` is Codable as `[lo, hi]`**; decoding `[48,12]` throws "Cannot initialize ClosedRange<Int> with a lowerBound (48) greater than upperBound (12)" under coding path `fontSizeRange`. Synthesized `Decodable` requires every key even with defaults (a missing `minSilence` ⇒ `keyNotFound`): the written file always carries all ten keys and a file missing one is invalid (DECISIONS: no partial files, no per-key defaults).
3. **`ConfigStore`, `DirectoryWatcher` and `FontSizeItem` were compiled and driven** (`scratch/s14-probe/`, `swiftc -O -swift-version 5`, no FluidAudio): defaults written on first run; in-place, atomic and delete+create edits each seen; seven invalid files each kept the previous value with a reason; two `changes()` subscribers both woken by one `set`; `set` out of range or on an invalid file throws and leaves the file untouched; slider action at 30.6 ⇒ thumb 31, file 31; six back-to-back actions ⇒ file 25; a file missing `minSilence` ⇒ error shown. The probe files are the code.
4. **Where config is read.** Only `SourcePipeline.swift:31` (run start), `:90` (every VAD start event) and `:111` (after a force-cut): an edit changes `minSilence`, speaker settings and `maxSegment` for the **next segment** of a running source with no code change. `render` takes `config` per call; `Overlay.draw` reads `config.current` per draw and redraws on `changes()` (S11).
5. **`ConfigStore` keeps `current` as a stored property**, so every reader compiles unchanged; `ConfigStore()` (in memory, no file) stays for `makeEngine`, `verify`'s `AppController.start` and earlier tests. `set` becomes `throws`; no caller outside `Config.swift` exists (grep). `changes()` returns a fresh stream per call: one stored `AsyncStream` would split elements between its consumers (font item, overlay).
6. **Slider.** `NSMenuItem.view` takes any `NSView`; an `NSSlider` in it receives mouse tracking from the menu. A real menu drag cannot be driven here: Minh's gate; in-process the action is sent with `sendAction`. Snapping is in the action (`doubleValue.rounded()`), no tick marks. A drag writes at most once per integer and each write returns as a `changes()` event that would reset the thumb to an older value while the mouse is further along, so `show()` leaves the thumb alone while the left button is down (`NSEvent.pressedMouseButtons & 1`). Slider actions fire ~60 per second: one `AsyncStream<Int>` (`bufferingNewest(1)`) with one consuming task serializes the writes and drops superseded values, so the last value lands last.
7. **Count at 0.25.** DECISIONS: VAD segmentation alone gives 16 segments at 0.25 and the 12 turns at 0.5; S2 measured the live pipeline at 14 lines at 0.5. The live pipeline's count at 0.25 (force-cuts and speaker splits included) was **not measured**; build step 3 measures it once and pins it.
8. **Composition.** `Session` owns the one file-backed `ConfigStore`, opened once in `main.swift`; `AppController.init` receives it. `FontSizeItem` owns its slider, value, error line and subscriptions; main passes its `item` to `MenuBar(settings:)`.
